# Процедура обслуживания скилла (Режимы 5 и 6)

> Цель — обновлять и докручивать скилл детерминированно, человек в контуре,
> с версионированием и повторной валидацией. Без скрытого состояния и без
> автономной мутации.

## Роутинг правки → файл

| Что меняется | Файл |
|---|---|
| Факт объекта (цена, удобство, координаты, контакты, сценарий) | `papino-profile.md` |
| GAP-ответ владельца | `papino-profile.md` (закрыть пункт → раздел «Подтверждено владельцем» с датой) |
| Приём/хук/антипаттерн | `marketing-playbook.md` |
| Критерий качества / стоп-лист | `post-criteria.md` |
| Тип поста (посыл) / тематический столп | `content-pillars.md` (имена синхронны с `post-criteria.md`!) |
| Форматное правило/число | `format-rules.md` (число не из ресерча → пометка «практика») |
| Сценарий/триггер/фраза гостя | `guest-insights.md` |
| Свежий ресерч | сначала дополнить `docs/smm/smm-research-*.md`, потом дистиллировать в нужный reference |

## Режим 5 — применить обновление

1. Определи файл по таблице. Внеси точечную правку.
2. GAP-ответ → перенеси пункт из «GAP-лист» в «Подтверждено владельцем (ДАТА)».
3. Проверь инвариант: имена посылов в `content-pillars.md` и `post-criteria.md`
   совпадают 1:1; нумерация стоп-листа сплошная.
4. **Ре-валидация (обязательно):** дистанцируй свежий субагент (general-purpose,
   sonnet, fresh context — НЕ передавать историю). Промпт: «Прочитай скилл в
   `~/.claude/skills/papino-smm/`. Часть A — регрессия Режимов 1–4 на
   представительных запросах (атмосферный пост; контент-план на 2 нед; разбор
   слабого поста; оценка статистики), аудит каждого выхода по
   `references/post-criteria.md` (Слой 1 + оверлей + стоп-лист). Часть B —
   прогон Режима 5 (симулируй новый факт владельца) и Режима 6 (пополни gap /
   ревизия): роутинг однозначен? ре-валидация обязательна? авто-коммит и
   авто-мутация запрещены? самозапуска нет? Safety: 0 “Яна”; имена гостей только
   из публичных Яндекс-отзывов; нет выдуманных фактов; приватные/семейные детали
   владельца не в контенте; нет “кошки”. Верни pass/fail + SKILL DEFECTS или
   NO DEFECTS. Файлы не менять.» Дефекты → почини → перепрогони, пока не чисто.
5. Синхронизируй снапшот в `<papinovillage>/docs/skills/papino-smm/`.
   - PowerShell (штатная среда проекта):
     `Copy-Item -Recurse -Force "$env:USERPROFILE\.claude\skills\papino-smm\*" "C:\Users\kulle\IdeaProjects\papinovillage\docs\skills\papino-smm\"`
   - Git Bash: `cp -rf /c/Users/kulle/.claude/skills/papino-smm/* /c/Users/kulle/IdeaProjects/papinovillage/docs/skills/papino-smm/`
6. Коммит — ТОЛЬКО по явной команде пользователя. Conventional Commits, без
   Co-Authored-By, ветка `feature/papino-smm-skill` (не main). Сообщение —
   краткое описание правки.

## Режим 6 — ревизия GAP и докрутки

1. Покажи открытый GAP-лист из `papino-profile.md` → короткий список вопросов
   владельцу (что ещё нужно, чтобы закрыть пробелы).
2. Открой `feedback-journal.md`. Покажи записи. Запись → правка критерия ТОЛЬКО
   при: (а) доказательной опоре (своя статистика за период / новый ресерч) И
   (б) явном подтверждении пользователя. Иначе остаётся наблюдением.
3. Сформулируй конкретные предложения: файл, что меняем, основание, риск.
4. По решению пользователя — выполни через Режим 5 (с ре-валидацией).

## Чего скилл НЕ делает (границы)

- Не запускает себя по расписанию / в конце сессии. Авто-триггер — это Stop-хук
  в `settings.json` либо `/schedule`-рутина, отдельно от скилла.
- Не правит критерии/плейбук «от фидбэка» без подтверждения и доказательной опоры.
- Не выдумывает факты для закрытия GAP — нет данных, остаётся в GAP-листе.
