# Дизайн: SMM-скилл для Papino Village (`papino-smm`)

- **Дата:** 2026-05-17
- **Статус:** утверждён к реализации (брейншторм пройден)
- **Тип:** персональный Claude Code скилл (знаниевая база + процесс генерации)

## 1. Цель и проблема

VK-группа Papino Village (vk.com/papino_village): ~10K подписчиков, ER ~0.3% — очень
низкий, охваты 700–1900, реакции 2–6. Нужен переиспользуемый инструмент, который пишет
сильные посты/Stories/клипы/Telegram-посты под конкретный объект — на основе
доказательных маркетинговых приёмов, реальной фактуры объекта и проверяемых критериев
качества, а не «из головы».

Скилл затачивается **только под Papino Village** (глэмпинг, 2 А-фрейм домика, 65 км от
Москвы по Калужскому шоссе): факты, УТП, инсайты из отзывов и тон бренда зашиты внутрь.
Он не переиспользуется для других объектов — это осознанное сужение ради качества
«из коробки».

## 2. Ключевые решения (зафиксированы на брейншторме)

| Развилка | Решение |
|---|---|
| Заточка | Только Papino Village (факты/УТП/инсайты/тон — внутрь скилла) |
| Каналы и форматы | VK посты, VK Stories, VK клипы, Telegram-канал — 4 блока форматных правил |
| Глубина ресерча | Глубокий live веб-ресерч (отдельная фаза реализации) |
| Источник фактуры объекта | Существующий `smm-content-plan.md` (первичный) + сайт + VK + память → твёрдое в БД, пробелы → gap-лист |
| Архитектура | Подход A: SKILL.md + references/ + templates/ + examples/ |
| Контент-план | Скилл **производит** план как выходной артефакт по запросу; **не хранит** состояние внутри себя |
| Критерии качества | Доказательные: выводятся из ресерча, не пишутся заранее |
| Лицо бренда | Только Михаил либо безличный голос. **Яна нигде** — сквозное ограничение |

### Почему НЕ «контент-движок со статусами/календарём» (отклонённый вариант C)

Скилл — это стабильное знание + процесс; он почти не протухает. Банк идей со статусами
и календарём — это данные с состоянием, требующие ручного ведения, иначе за неделю
расходятся с реальностью (что уже опубликовано, что отснято, какой был ER).
Существующий `docs/papinovillage/smm-content-plan.md` (v4, 2026-05-10, 947 строк,
закоммичен и отслеживается — не потерян) подтверждает модель: это ценный
**входной и выходной артефакт**, который живёт в репо/доках и ведётся владельцем, а не
состояние внутри скилла. Скилл использует его как образец формата и источник фактуры и
**регенерирует/дополняет** такой артефакт по запросу — но не хранит и не синхронизирует
его состояние сам. Осмысленный календарь требует данных о публикациях/аналитике, которых
у статичного скилла нет. Поэтому: скилл **генерит** план на N постов по запросу, на свежих
вводных, и кладёт его как датированный артефакт **вне скилла**; ведёт план владелец.
Живой календарь, если понадобится, — отдельный проект с источником данных, не нагрузка
на скилл (YAGNI).

## 3. Размещение и структура

Персональный скилл (доступен в любой сессии и репозитории; SMM-работа не привязана к
коду конкретного репо):

```
~/.claude/skills/papino-smm/
  SKILL.md                  # когда использовать, 4 режима, ссылки на references, чек-лист
  references/
    papino-profile.md       # факты объекта + УТП + тон (только Михаил) + GAP-лист
    guest-insights.md       # золото из отзывов: сценарии, триггеры, формулировки гостей
                            #   + правило обезличивания (Яна не упоминается)
    marketing-playbook.md   # дистиллят ресерча: хуки, заголовки, эмоц. триггеры,
                            #   виральные механики VK 2026, что заходит в нише
    format-rules.md         # правила по 4 каналам: VK пост / Stories / клип / Telegram
    content-pillars.md      # контент-столпы + таксономия типов постов (посыл)
    post-criteria.md        # критерии качества: универсальная база + оверлеи по посылу
  templates/                # скелеты: vk-post, vk-story, vk-clip, tg-post
  examples/                 # 1–2 эталона на формат (до/после + разбор почему сработало)
```

Выходные батч-планы пишутся в репозиторий papinovillage
(`docs/smm/YYYY-MM-DD-content-plan.md`), **не внутрь скилла**.

## 4. Четыре режима работы скилла

1. **Одиночный пост.** Вход: повод/тема/формат. → Доспросить пробелы по профилю →
   зафиксировать (столп, посыл, формат) → подобрать механику из плейбука → черновик →
   самопроверка по чек-листу → выдать: текст + визуал-бриф + альтернативный хук +
   «почему сработает».
2. **Батч / контент-план.** Вход: период, количество, микс форматов. → Разложить по
   столпам и поводам (сезон/события) → сгенерить N постов → собрать в датированный
   `docs/smm/YYYY-MM-DD-content-plan.md` в репо papinovillage с пометками статуса и
   «нужна съёмка». Артефакт живёт вне скилла; ведёт его владелец.
3. **Анализ существующего поста.** Вход: текст или URL. → Оценка по критериям →
   диагноз слабого ER (хук / структура / посыл / CTA / тема) → переписанная версия.
4. **Оценка статистики.** Вход: метрики по постам/рубрикам (охват, реакции, ER). →
   Интерпретация → что усиливать, какие столпы/форматы/посылы работают, рекомендации
   по частоте и микс-структуре.

## 5. Критерии качества — двухслойная модель

Конкретное наполнение обоих слоёв — **выход фазы ресерча**, не пишется заранее.

**Слой 1 — универсальная база (любой пост, любой посыл):**
- Хук в первой строке — цепляет за ~1.5 сек (до сворачивания текста VK)
- Одна мысль на пост
- Тон бренда: тёплый, от Михаила или безличный; без канцелярита и инфоцыганщины
- Фактическая достоверность: только подтверждённое профилем; пробел → пометка, не выдумка
- **Яна не упоминается** нигде; в цитируемых отзывах — обезличивание
- CTA под цель поста (бронь / сохранение / коммент / репост / дочитать)
- Формат-комплаенс канала (длина/структура)
- Приложен визуал-бриф
- Прошёл стоп-лист клише/антипаттернов

**Слой 2 — оверлей под посыл поста.** У каждого типа своё определение «сработал»
(финальная таксономия и точные критерии — из ресерча):
- *Атмосферно-эмоциональный* — сенсорика, сценарий гостя, вызывает желание поехать
- *Информационный* — точность, польза, сканируемость, отвечает на реальный вопрос
- *Развлекательный* — лёгкость, механика вовлечения (опрос/угадай/мем), не душнит
- *Продающий* — оффер, причина действовать сейчас, без впаривания
- *Вовлекающий / UGC* — явный триггер реакции (вопрос, спор, «отметь, с кем поедешь»)

Таксономия типов постов = поля в `content-pillars.md`; критерии (база + оверлеи) =
`post-criteria.md`.

## 6. Фаза ресерча (часть плана реализации, не самого скилла)

Глубокий веб-ресерч через параллельных агентов; результат дистиллируется в
`marketing-playbook.md`, `format-rules.md`, `content-pillars.md`, `post-criteria.md`,
`papino-profile.md`, `guest-insights.md`:

- Виральные механики VK 2026: умная лента, что даёт охват (репосты / сохранения /
  время просмотра / досмотры клипов)
- SMM глэмпинга и посуточной аренды в РФ: форматы, тон, посылы, успешные кейсы
- Разбор 3–5 конкурентов-глэмпингов в VK: типы контента, частота, что виралит
- Тренды форматов: механики Stories/клипов, хуки, длины, структуры
- Сбор фактуры Papino Village: **существующий `docs/papinovillage/smm-content-plan.md`
  (первичный источник: тон/owner-story, цены, акции, зачатки таксономии постов)** +
  сайт (репо/live) + VK-группа через веб + инсайты из памяти → `papino-profile.md`,
  `guest-insights.md`, `content-pillars.md` + gap-лист «нужно от владельца»

## 7. Жёсткий порядок реализации (зависимость)

1. **Ресерч** (фаза 6) — собрать находки.
2. **Из находок вывести** таксономию типов постов + критерии (база + оверлеи) +
   форматные правила + плейбук + профиль объекта + gap-лист.
3. **Собрать скилл**: SKILL.md (процесс + 4 режима + чек-лист), templates/, examples/.
4. **Валидация скилла** по канону writing-skills (skill работает на тестовом запросе
   каждого из 4 режимов).

Критерии приёмки не пишутся «из головы» до завершения фазы 1.

## 8. Вне скоупа (YAGNI)

- Хранение состояния контент-плана внутри скилла (статусы/даты/ротация)
- Календарь-движок с источником данных о публикациях — отдельный будущий проект
- Переиспользование скилла для других объектов (осознанно только Papino Village)
- Автопостинг / интеграция с VK API
- Генерация изображений/видео (скилл даёт визуал-бриф, не медиа)
